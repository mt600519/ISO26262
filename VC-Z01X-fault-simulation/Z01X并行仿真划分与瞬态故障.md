# Z01X并行仿真划分与瞬态故障

本文整理按模块划分故障活动、合并仿真结果、FMEDA 指标汇总，以及瞬态故障配置与统计方法。依据 VC Z01X User Guide X-2025.06-SP2 和 VC FSM V-2023.12-SP1 本机脚本；其他版本应核对对应手册与命令帮助。以下命令示例未在实际芯片活动上验证。

## 一、按模块拆分仿真是否可行

可以。FMEDA 不要求所有模块的故障在同一批仿真中运行。建议保留同一份芯片设计和验证环境，只拆分注错集合：

```text
同一芯片级设计和验证环境
├── 活动 A：模块 A 的注错点、观测点和诊断点
├── 活动 B：模块 B 的注错点、观测点和诊断点
└── 活动 C：模块 C 的注错点、观测点和诊断点
```

活动可分时运行或限制并发。如果改用独立模块 testbench，需要证明边界激励、跨模块错误传播、安全机制响应及诊断窗口能够代表芯片使用场景。尤其不能因为拆分模块而遗漏共享安全机制和公共逻辑。

### 资源限制

FCM 提供任务并发数和每个任务故障数两类限制，例如：

```tcl
set_config -global_max_jobs 4
set_config -max_faults_per_fsim_task 128
```

数值仅为小规模试跑起点，需根据内存和日志调整。前者限制任务并发，后者限制单任务故障规模。多个独立 FCM 同时运行时，应额外协调跨活动的资源总量。并发过多与单进程堆栈溢出并非必然同因，应先核对报错进程、内存及堆栈日志。

## 二、合并 Z01X 仿真结果

手册支持通过 vc_fcc 合并多个 Standard Fault Format 结果报告：

```bash
vc_fcc -full64 \
  -daidir simv.daidir \
  -sff moduleA_results.sff moduleB_results.sff moduleC_results.sff \
  -campaign chip_merged \
  -dut_path tb.top

vc_fdb_report -campaign chip_merged
```

这里输入的是包含 FaultList 和仿真状态的结果 SFF，而非仅含 FaultGenerate 的原始故障定义。不能直接拼接文件或相加各报告百分比。

合并前应保证：

- 设计版本、层级命名和编译配置一致；变更设计可能改变匿名 primitive 名称。
- 状态定义、PromotionTable 和 Coverage 公式兼容。
- FailureMode、诊断机制及其信号关联能够保留。
- 跨模块共享逻辑有明确统计归属，避免重复计入硬件失效率。
- 故障时间、类型、位置等标识保持完整，不把不同瞬态故障误合并。
- 检查失败、超时和部分结果，不能把未完成任务当成完整故障覆盖。

同一个故障在不同测试中的结果按 PromotionTable 合并，汇总故障数不是各测试故障数简单相加。模块故障集合的并集与同一故障跨 testcase 的状态合并，是不同层次的处理。需要先小规模验证合并后的故障数、状态分布、FailureMode 与覆盖率公式。

## 三、合并报告与 SPFM/LFM 汇总的区别

推荐工作流：

```text
各模块独立故障活动
  → 获得各 FailureMode 的 Fsafe、DC(Krf)、DC(Kmpf)
  → 分别回标 VC FSM
  → Synthetic Hierarchy 汇总芯片 SPFM/LFM
```

无需先建立一个巨大的合并 FDB 才能计算芯片指标。总故障报告可另行生成，用于追溯与完整性检查。

不得对模块 DC、SPFM、LFM 做算术平均。例如同一口径下，模块 A 危险故障失效率 10 FIT、DC=90%，模块 B 为 90 FIT、DC=50%，对应失效率加权 DC 为：

```text
(10 × 0.90 + 90 × 0.50) / 100 = 54%
```

不是 70%。故障数量加权也不自动等于 FMEDA 的失效率加权；需考虑故障映射、代表性、采样权重和硬件失效率分配。

VC FSM 应按失效模式失效率及安全分类汇总 SPF、RF、潜伏多点故障等贡献。SPFM 的计算形式为：

```text
SPFM = 1 − (ΣλSPF + ΣλRF) / ΣλSR
```

LFM 需要考虑潜伏故障、安全机制自身故障、相关诊断及时间参数，不能仅凭合并后的单个 DC 推导。分模块并不取消多点故障、共因和依赖失效分析要求；需要验证的跨模块场景仍要另行覆盖。

## 四、瞬态故障的时间语法

```text
Timing("cycle1", CycleTime 20ns, Offset 2ns)
UseTiming("cycle1")
NA ~ (1:60) { FLOP "tb.dut.**" }
```

- cycle1 是时间配置名称，不是第一个周期。
- CycleTime 是故障时间换算周期，不会自动产生或连接设计时钟。
- UseTiming 指定后续故障采用的时间配置。
- ~ 表示瞬态翻转。
- (1:60) 包含两端，为每个适用位置展开第 1 至第 60 周期的独立故障候选。

对单个适用 bit，在未采样、排除或合并等处理前，这对应 60 个注错时刻；不是一个故障连续翻转 60 次，也不是保持 60 周期。具体注错时刻还受 Offset、注错开始配置和仿真调度影响。

### 范围与保持区间

```text
NA ~ (1:60) { FLOP "tb.dut.ff" }  # 按各周期展开
NA ~ (1^60) { FLOP "tb.dut.ff" }  # 在起始周期翻转，保持至结束周期释放
```

冒号和 ^ 不可互换。顺序单元释放后的值何时恢复还取决于后续更新；组合输出的释放行为不同。START、END 在本生成脚本中作为周期编号输入，不是 ns 字符串。

## 五、不同注错周期如何计入 DC

假设单 bit 信号 A 使用 (1:60)，只在第 9 周期的故障被观测且诊断，其余 59 个均未观测且未诊断：

```text
1 个 OD + 59 个 NN
```

不同时间的故障分别统计，不因一个周期被检测就把整个信号 A 记为 OD。若等权且没有其他处理，采用本文模板公式时该集合的 DC 为 1/60，约 1.67%。最终 FailureMode 的 DC 需统计它的全部故障。

仅知道未诊断并不能判为 NN：

| 状态 | 含义 |
| --- | --- |
| NN | 未观测、未诊断 |
| ON | 已观测、未诊断 |
| ND | 未观测、已诊断 |
| OD | 已观测、已诊断 |

此表为模板自定义功能安全状态；与工具原生同名状态要区分，模板会先重命名部分原生状态。OD 和自定义 ND 都纳入模板的 DD 组。不同 testcase 对同一个故障的状态提升，也不能与不同注错周期的独立统计混淆。

## 六、瞬态对象类型与选点限制

手册第 90 页明确列出 ~ 模型支持 ARRY、PORT、VARI、FLOP；第 91 页又讨论 PRIM 的放置，因此存在表述差异。当前生成脚本采用明确列出的四种，不将 PRIM 作为已验证选项。

| 类型 | 关键要求 |
| --- | --- |
| ARRY | 对应受支持的数组／存储器对象；实际元素类型和展开方式需核对 |
| PORT | 瞬态不允许输入位置；通配符生成会限制至输出；手册还要求相应位置能够回溯时序单元，否则可能警告且不生成 |
| VARI | 必须是受支持的实际变量，不能将连接寄存器的 wire 当作变量 |
| FLOP | 对应工具识别的触发器、锁存器或时序 UDP；从端口或实例位置使用，可能回溯驱动存储单元 |

WIRE 不在上述 ~ 模型支持列表中。PORT 还依赖端口故障编译配置。永久 PORT 输入故障与瞬态 PORT 输入限制不同。

FLOP 在启用了端口故障的模块上可能只覆盖与输出／inout 连接的时序单元，不能假设扫描全部内部寄存器。VARI 用于数组时按 word 展开，而 VARI/ARRY 用于向量时按 bit 展开；应核对实际故障列表，不仅检查 SFF 语法。

## 七、瞬态故障 Exclude

位置排除示例：

```text
FaultGenerate CFG_FM_2 {
    Timing("cycle1", CycleTime 20ns, Offset 2ns)
    UseTiming("cycle1")
    NA ~ (1:60) { FLOP "tb.dut.cfg.**" }

    Exclude {
        * * (*) { FLOP "tb.dut.cfg.exclude_ff1" }
        * * (*) { FLOP "tb.dut.cfg.exclude_ff2" }
    }
}
```

通配的状态、类型与时间表示不限定这些字段，按位置和对象类过滤。用 `*` 替代 FLOP 可放宽对象类型，但范围更大，需谨慎核对。该位置排除适用于单故障源，不适用于 MFO。路径应匹配实际生成的位置，尤其关注 FLOP 回溯。

手册还说明，同一故障若属于多个 FailureMode，在一个中被排除后也可能在其他模式中被排除，不能把它当成互相隔离的局部过滤。建议小样本导出 FaultList 检查排除效果。

## 八、NC/Unselected 对模板 DC 的影响

模板定义 NC 属于 NG（Unselected）组，当前公式为：

```text
DC(Krf)  = DD / (NA + AF + NG + HG + AU + DN + DD + FN)
DC(Kmpf) = DD / (NA + AF + NG + HG + AU + DN + DD + FN)
```

最终仍为 NC 的故障进入分母但不进入分子，会降低 DC。90 个 DD、10 个 NC 且其他为零时，DC 为 90%。NC 是当前 workload 下未控制，不等于结构上安全。多 testcase 合并后应以最终状态统计。

模板的 DC2/DC3 不含 NG，但不能仅为提升结果就更换公式，应明确统计口径和排除依据。安全故障比例 Fsafe 与诊断覆盖率也应分别计算和回标。

## 九、strobe 使用 SFF 的观测点和诊断点

```systemverilog
integer obs_cmp;
integer det_cmp;
obs_cmp = $fs_observe();
det_cmp = $fs_detect();
```

它们分别读取故障关联的 FailureMode 中 Observe 和 Detect／SafetyMechanisms 对应信号，比较同一信号的 GM/FM 值，不是把列表中的信号互相比。

返回值 0 表示没有报告差异，1 为确定差异，2 为 GM=0/1 而 FM=X/Z 的潜在差异；确定差异优先。使用 integer 等能保存 0/1/2 的变量。函数仅在 FM 中有效，在 GM 中返回 0。

替换 $fs_compare 后仍要保留合适的采样时刻、诊断时间窗口及状态设置逻辑；函数不会自动把结果赋为 OD/NN。诊断是否要求报警为 1 等额外条件也不会自动建立。FaultGenerate/FaultList 必须保留正确 FailureMode 关联。
